# Issue #1166: new personal Shows through UI and MCP

`e2e/agent-mcp-replacement.auth.spec.ts` contains two authenticated ordinary-browser cases. Each starts with the Studio creation flow for a named Portable Show on `plane` at 1,024 preview pixels. The only setup writes are the synthetic red and green Patterns. The Show UUID and starter V2 record come from the UI's own create action; the test checks that UUID was absent from the account before creation and that the named Show appears in the personal rail rather than Built-in Shows.

The incremental case removes the UI's two starter Clips and now-empty Layer through real MCP, shortens Show End to 1,000 ms, commits and checks a complete empty durable composition. A second MCP edit creates one Layer and two adjacent red/green Clips. It derives only opaque identity tokens from command replies and constructs the expected authored record independently. The upload case uses a separate UI-created Show and replaces its complete composition through MCP, retaining the UI-created id and name. Neither case describes the creation UI as blank.

Both cases compare complete saved records before and after reload, selected personal rail rows, real fixed-time 32×32 centre samples at 250 and 750 ms, a rejected wrong-image expectation, and zero browser errors. Each downloads the `.pxlshow` and `.epe` through Show actions after reload. The `.pxlshow` is parsed through the product importer and its reopened Show must equal the saved record. The `.epe` is parsed from the actual download; its Show stamp, output contract, source hash, and render export are checked. Ignored `playwright-report/agent-mcp/` run packages retain PNGs, both downloads, hashes, byte counts, safe MCP transcripts, and focused timing. No LLM call participates in execution or judging.

The implementation-focused authenticated Playwright run passed both cases with two workers in 17.0 seconds. Its ignored manifests are `playwright-report/agent-mcp/6ad9ee95394cf3ff-worker-0-retry-0-repeat-0/create-sequence.json` and `playwright-report/agent-mcp/f3618df7521f213b-worker-1-retry-0-repeat-0/create-upload.json`; each sits beside four PNGs and the two downloaded files. Both manifests report zero browser errors and successful artifact reopen checks. A sandboxed run could not launch Chromium because macOS denied Mach port registration; the passing run used host execution.
